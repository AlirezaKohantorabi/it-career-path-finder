# راهنمای توسعه، تست و انتشار

برای کسانی که روی کد افزونه کار می‌کنند. توضیح کامل معماری: [../PROJECT.md](../PROJECT.md)؛ توضیح تک‌تک فایل‌ها و تابع‌ها: [../code/README.md](../code/README.md).

## ۱. شروع کار

۱. دعوت‌نامه همکاری (Collaborator) را از ایمیل یا از [github.com/notifications](https://github.com/notifications) قبول کنید.
۲. مخزن را کلون کنید:

```bash
git clone https://github.com/AlirezaKohantorabi/it-career-path-finder.git
```

۳. برای دیدن تغییرها در یک وردپرس محلی، پوشه مخزن را داخل `wp-content/plugins/it-career-path-finder` بگذارید (یا لینک بدهید) و افزونه را فعال کنید. روش ساخت وردپرس محلی بدون MySQL در [../TESTING.md](../TESTING.md) آمده است.

## ۲. ساختار کلی

| پوشه | چه چیزی |
|---|---|
| `data/` | همه محتوا (سؤال‌ها، شغل‌ها، متن‌ها، وزن‌ها) به شکل JSON |
| `src/` | کلاس‌های PHP: `Data` (خواندن و ذخیره شغل‌ها)، `Frontend` (شورت‌کد و فایل‌ها)، `Admin` (صفحه‌های پیشخوان) |
| `templates/` | HTML صفحه‌ها |
| `assets/js/` | کد مرورگر: ۱۸ ماژول کوچک (امتیازدهی، نمایش سؤال، نمایش نتیجه و…) |
| `assets/css/` | ظاهر ابزار و صفحه‌های پیشخوان |
| `tests/` | تست‌ها |
| `docs/` | مستندات؛ `docs/code/` برای هر فایل کد یک صفحه دارد |

## ۳. قانون‌های کدنویسی

- **هر تابع فقط یک کار.** اگر برای توضیحش «و» لازم شد، دو تابع کنید.
- **اسم تابع بگوید چه کار می‌کند.** مثل `missing_required_fields()`.
- **کامنت ننویسید.** «چه» را اسم‌ها می‌گویند و «چرا» را مستندات (`docs/`).
- **عدد جادویی نه.** ثابت با اسم بسازید یا عدد قابل تنظیم را در `data/scoring.json` بگذارید.
- **امنیت:** هر ورودی پاک‌سازی، هر خروجی escape، هر عملیات پیشخوان با بررسی دسترسی و nonce. هیچ‌وقت `innerHTML` استفاده نکنید. قبل از تغییر عملیات پیشخوان [../SECURITY.md](../SECURITY.md) را بخوانید.
- متن‌هایی که کاربر سایت می‌بیند در `data/interface-text.json`؛ متن‌های پیشخوان با `__()`.

جزئیات بیشتر: [../../CONTRIBUTING.md](../../CONTRIBUTING.md)

## ۴. قانون مستندسازی

با هر تغییر کد:

- صفحه همان فایل در `docs/code/` را به‌روز کنید (تابع جدید، تغییر نام، ارتباط با فایل‌های دیگر).
- اگر بین چند راه یکی را انتخاب کردید: یک بند جدید در `docs/DECISIONS.md`.
- اگر اشتباه یا باگی پیدا کردید که ارزش یادآوری دارد: یک بند جدید در `docs/LESSONS.md`.
- همیشه: `CHANGELOG.md`.

اگر فایلی صفحه مستند نداشته باشد یا اسم تابعی در صفحه‌اش نیامده باشد، تست‌ها خطا می‌دهند.

## ۵. اجرای تست‌ها

```bash
php tests/run.php
```

تست‌های جاوااسکریپت: در پوشه مخزن `php -S localhost:8090` را اجرا کنید و `http://localhost:8090/tests/js/run.html` را در مرورگر باز کنید. عنوان صفحه باید `PASS` باشد.

با هر push، گیت‌هاب در تب **Actions** تست‌ها را اجرا می‌کند و فایل zip افزونه را هم می‌سازد.

## ۶. ساختن فایل zip

```bash
php tools/build-zip.php
```

فایل در `dist/it-career-path-finder-<نسخه>.zip` ساخته می‌شود و فقط فایل‌های لازم برای اجرای افزونه را دارد.

## ۷. انتشار نسخه جدید

۱. شماره نسخه را انتخاب کنید: رفع اشکال `1.0.1`، امکان جدید `1.1.0`، تغییر ناسازگار `2.0.0`.
۲. نسخه را در **چهار جا** عوض کنید:
   - `Version:` بالای `it-career-path-finder.php`
   - `define( 'ITCP_VERSION', … )` در همان فایل
   - `Stable tag:` در `readme.txt` (و یک خط در بخش `== Changelog ==` همان فایل)
   - یک تیتر جدید `## [x.y.z] — تاریخ` در `CHANGELOG.md` که می‌گوید چه چیزی و چرا عوض شد
۳. تست‌ها را اجرا کنید.
۴. commit و push کنید، بعد تگ بزنید:

```bash
git tag v1.0.1
```

```bash
git push origin main --tags
```

۵. گیت‌هاب خودکار فایل zip را می‌سازد و به صفحه Releases اضافه می‌کند. همان فایل را روی سایت نصب کنید ([SETUP.fa.md](SETUP.fa.md) بخش ۶).



