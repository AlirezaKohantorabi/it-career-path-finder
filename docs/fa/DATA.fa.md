# راهنمای تغییر شغل‌ها، سطح‌ها، سؤال‌ها و متن‌ها

همه محتوای ابزار در پوشه `data/` و در پنج فایل JSON جداست. این راهنما می‌گوید برای هر تغییر کدام فایل را باز کنید و چه چیزی را عوض کنید. نسخه انگلیسی و جزئیات فنی: [../DATA.md](../DATA.md).

## دو راه برای تغییر شغل‌ها

| راه | کی استفاده کنیم | کجا ذخیره می‌شود |
|---|---|---|
| **پیشخوان وردپرس** (مسیر شغلی IT ← افزودن شغل) | تغییر روی یک سایت مشخص، سریع و بدون کدنویسی | پایگاه داده همان سایت |
| **فایل `data/roles.json` در گیت‌هاب** | تغییری که باید در نسخه بعدی افزونه برای همه باشد | داخل خود افزونه |

نکته: اگر در پیشخوان کلی شغل اضافه یا ویرایش کرده‌اید و می‌خواهید آن‌ها را دائمی کنید، از «درون‌ریزی و برون‌بری» فایل JSON بگیرید؛ این فایل دقیقاً هم‌قالب `data/roles.json` است و می‌توانید در گیت‌هاب جایگزینش کنید.

## کدام فایل برای چه کاری؟

| می‌خواهم… | فایل |
|---|---|
| شغل اضافه/حذف کنم یا سطح‌های یک شغل را عوض کنم | `roles.json` |
| متن یا گزینه‌های یک سؤال، یا راهنمای زیر سؤال را عوض کنم | `questionnaire.json` |
| متن دکمه‌ها، عنوان‌ها، دلیل‌ها، هشدارها یا برنامه ۳۰ روزه را عوض کنم | `interface-text.json` |
| یک دسته‌بندی، علاقه یا محیط کار جدید بسازم | `vocabulary.json` |
| اهمیت (وزن) عامل‌ها یا جریمه‌ها را عوض کنم | `scoring.json` |

## اضافه کردن شغل جدید در `roles.json`

ساده‌ترین راه: یک شغل شبیه را کپی کنید و تغییرش بدهید. هر شغل بین `{` و `}` است و شغل‌ها با کاما `,` از هم جدا می‌شوند (بعد از آخرین شغل کاما نگذارید).

```json
{
  "id": "shopify_developer",
  "title_fa": "توسعه‌دهنده شاپیفای",
  "title_en": "Shopify Developer",
  "category_id": "software_development",
  "plain_description": "توضیح خیلی ساده و غیرفنی: این شغل چیه و طرف دقیقاً چی کار می‌کنه.",
  "ratings_1_to_5": {
    "entry_difficulty": 3,
    "relative_market_opportunity": 2,
    "income_ceiling": 3,
    "job_stability": 3,
    "insurance_likelihood_in_employee_roles": 2,
    "stress_level": 3,
    "responsibility_level": 3,
    "routine_level": 3,
    "work_mode_fit": { "remote": 5, "hybrid": 4, "onsite": 3 },
    "client_type_fit": { "individual": 3, "small_business": 5, "medium_large_organization": 2, "public_sector": 1 },
    "work_arrangement_fit": { "employee": 3, "freelance": 5, "project_contract": 4, "consultant": 3, "self_employed": 4 }
  },
  "interest_tags": ["coding", "business", "visual"],
  "typical_workplaces": ["ecommerce", "digital_agency", "freelance"],
  "essential_skills": ["HTML/CSS", "Liquid", "JavaScript"],
  "recommended_entry_route": "یک فروشگاه آزمایشی کامل بسازید و منتشرش کنید.",
  "market_caveat": "بازار این ابزار در ایران کوچک است و بیشتر مشتری خارجی دارد.",
  "labels": ["remote_compatible", "freelance_possible"]
}
```

قانون‌ها:

- **`id`** یکتا باشد، فقط حروف کوچک انگلیسی، عدد، `_` و `-`. **هیچ‌وقت شناسه یک شغل موجود را عوض نکنید**؛ تغییرهای پیشخوان با همین شناسه ذخیره شده‌اند.
- **`plain_description`** لازم است: به زبان خیلی ساده، بدون اصطلاح فنی، با یک مثال از زندگی روزمره. این متن اول کارت شغل نمایش داده می‌شود.
- **`category_id`** یکی از `id`های بخش `categories` در `vocabulary.json` باشد.
- **`interest_tags`** و **`typical_workplaces`** و **`labels`** فقط از مقدارهای `vocabulary.json` (بخش‌های `interest_tags`، `workplace_types`، `role_labels`) باشند.

## سطح‌ها (عددهای ۱ تا ۵)

همه سطح‌ها عدد صحیح بین ۱ تا ۵ هستند. ۳ یعنی متوسط.

| کلید | معنی | ۱ یعنی | ۵ یعنی |
|---|---|---|---|
| `entry_difficulty` | سختی ورود | ورودش آسان است | یادگیری طولانی و سخت لازم دارد |
| `relative_market_opportunity` | فرصت شغلی در ایران | کار کم پیدا می‌شود | کار زیاد پیدا می‌شود |
| `income_ceiling` | سقف درآمد در بلندمدت | سقف پایین | سقف خیلی بالا |
| `job_stability` | ثبات شغلی | پروژه‌ای و پرنوسان | ثابت و قابل پیش‌بینی |
| `insurance_likelihood_in_employee_roles` | احتمال بیمه در استخدام | کم | زیاد |
| `stress_level` | فشار کاری | آرام | ددلاین و کار فوری زیاد |
| `responsibility_level` | میزان مسئولیت | کارهای مشخص | تصمیم‌گیری نهایی |
| `routine_level` | روتین بودن | هر روز کار متفاوت | تکراری و منظم |
| `work_mode_fit` | تناسب با دورکاری/ترکیبی/حضوری | کم | زیاد |
| `client_type_fit` | تناسب با هر نوع مشتری | کم | زیاد |
| `work_arrangement_fit` | تناسب با هر شیوه کار | کم | زیاد |

چند نکته مهم درباره اثر عددها:

- `entry_difficulty` بالاتر از ۳: برای کسی که تازه شروع کرده و کمتر از ۳ ماه وقت دارد، جریمه دارد.
- `work_mode_fit.remote` کمتر از ۳: برای کسی که فقط دورکاری می‌خواهد، جریمه دارد.
- `insurance_likelihood_in_employee_roles` کمتر از ۳: برای کسی که بیمه برایش شرط حتمی است، جریمه دارد.
- `stress_level` ۴ یا ۵ (یا برچسب `high_stress_or_urgency_possible`): برای کسی که آن‌کال را قبول نمی‌کند، جریمه دارد.
- هر جریمه، شغل را از گروه «پیشنهادی» به گروه «با کوتاه آمدن» می‌برد.

## تغییر سؤال‌ها در `questionnaire.json`

- متن سؤال (`title`)، راهنما (`hint`) و متن گزینه‌ها (`label`) را **آزادانه** عوض کنید.
- **`id` سؤال و `value` گزینه‌ها را عوض نکنید**؛ کد امتیازدهی با همین‌ها کار می‌کند.
- ترتیب سؤال‌ها همان ترتیب داخل فایل است. با جابه‌جا کردن، ترتیب در ابزار هم عوض می‌شود.
- هر سؤال یک `section` دارد که باید یکی از `id`های بخش `sections` باشد. عنوان بخش‌ها (مثل «هدف‌ها و شیوه کار») را هم همان‌جا عوض کنید.
- اگر سؤال جدید اضافه کنید، نمایش داده و جوابش ذخیره می‌شود، ولی تا وقتی در کد امتیازدهی (`assets/js/scoring.js`) استفاده نشود، روی نتیجه اثری ندارد.

## تغییر متن‌ها در `interface-text.json`

هر متنی که کاربر می‌بیند (غیر از سؤال‌ها و شغل‌ها) اینجاست. چیزهای داخل آکولاد مثل `{count}` یا `{title}` را **دست نزنید**؛ کد جایشان عدد یا اسم می‌گذارد. می‌توانید جایشان را در جمله عوض کنید.

## تغییر وزن‌ها و جریمه‌ها در `scoring.json`

- `weights`: اهمیت هر عامل (الان جمعشان ۱۰۰ است). مثلاً اگر می‌خواهید علاقه مهم‌تر باشد، `interest_match` را بیشتر کنید.
- `penalties`: چند امتیاز از شغل‌های دارای تعارض کم شود.
- `grouping`: حداقل امتیاز برای «پیشنهادی» (`primary_min_score`)، حداکثر تعداد هر گروه و…
- اسم کلیدها را عوض نکنید.

## نکته‌های نوشتن فارسی

- از نیم‌فاصله (ZWNJ) استفاده کنید: «می‌کند»، «شغل‌ها». در ویندوز: Ctrl+Shift+2، در کیبورد استاندارد فارسی: Shift+Space.
- علامت نقل‌قول انگلیسی `"` داخل متن JSON باید به شکل `\"` نوشته شود؛ بهتر است از گیومه فارسی «» استفاده کنید.

## بعد از هر تغییر

۱. درستی JSON را چک کنید: ویرایشگرهایی مثل VS Code خطا را قرمز نشان می‌دهند، یا متن را در [jsonlint.com](https://jsonlint.com) بچسبانید.
۲. اگر روی کامپیوترتان PHP دارید، `php tests/run.php` را اجرا کنید؛ شناسه تکراری، سطح خارج از ۱ تا ۵، دسته ناشناخته یا متن جاافتاده را دقیق می‌گوید.
۳. در گیت‌هاب بعد از push، تب **Actions** همین تست‌ها را خودکار اجرا می‌کند؛ اگر تیک سبز نبود، رویش بزنید تا خطا را ببینید.
۴. تغییر را در `CHANGELOG.md` بنویسید.
